# pulsecrm-sync — серверная база сделок

Воркер один раз выгружает сделки клиента из Bitrix24 и дальше каждые 5 минут докачивает изменения.
Дашборд при открытии берёт сделки у воркера и не качает тысячи страниц из Bitrix24, поэтому быстро
грузится уже с первого открытия. Пока воркер не развёрнут, дашборд работает как раньше.

Файлы:
- `sync-worker.js` — код воркера
- `sync-worker-schema.sql` — схема базы D1

## Развёртывание (Cloudflare Dashboard, ~10 минут)

**0. Тариф.** Нужен **Workers Paid** ($5/мес): Workers & Pages → Plans.
На бесплатном тарифе воркеру не хватит лимитов: 10 мс CPU на запуск, 50 внешних запросов за запуск
и 100 000 записей в D1 в сутки. Первая выгрузка клиента с 200к сделок в эти лимиты не укладывается.

**1. База D1**
1. dash.cloudflare.com → **Storage & Databases → D1** → **Create database** → имя `pulsecrm-sync` → Create.
2. Открыть базу → вкладка **Console** → вставить целиком содержимое `sync-worker-schema.sql` → **Execute**.

**2. Воркер**
1. **Workers & Pages** → **Create** → **Create Worker** → имя `pulsecrm-sync` → **Deploy**.
2. **Edit code** → стереть всё → вставить целиком `sync-worker.js` → **Deploy**.

**3. Привязка базы**
Воркер `pulsecrm-sync` → **Settings → Bindings** → **Add** → **D1 database** →
Variable name: `DB` (строго так), Database: `pulsecrm-sync` → Save.

**4. Расписание**
Воркер → **Settings → Triggers** → **Cron Triggers** → **Add** → `*/5 * * * *` → Save.

**5. Адрес**
Скопируйте адрес воркера вида `https://pulsecrm-sync.<ваш-аккаунт>.workers.dev` и пришлите его —
он вписывается в `SYNC_URL_DEFAULT` в `dashboard.html`.

## Проверка

- Открыть в браузере `https://pulsecrm-sync.<аккаунт>.workers.dev/status` — должно вернуть
  `{"registered":false}` (без вебхука так и должно быть).
- Проверить на себе до выката всем. Откройте дашборд, F12 → Console и выполните:
  `localStorage.pCRM_syncUrl = 'https://pulsecrm-sync.<аккаунт>.workers.dev'`, затем обновите страницу.
  Первое открытие регистрирует портал, и воркер начинает выгрузку в фоне
  (200к сделок — это 2–3 запуска cron, 10–15 минут). После этого в консоли появится
  `[загрузка] сервер: N сделок …`.
- Состояние портала в D1 Console: `SELECT phase, full_done, cursor, last_modified, error FROM portals;`

## Как это работает

- `POST /register` — дашборд регистрирует портал при открытии. Вебхук проверяется запросом к Bitrix24.
- cron каждые 5 минут. Для новых порталов идёт первичная выгрузка: продолжается с места остановки
  между запусками, до ~75к сделок за запуск. Для готовых — докачка изменённых (`DATE_MODIFY`).
  Раз в сутки — полная сверка, которая заодно удаляет сделки, удалённые в CRM.
- `GET /deals` отдаёт сделки из базы по воронке, периоду и «только выигранные». Дашборд сверху
  докачивает из Bitrix24 то, что изменилось после последней синхронизации сервера, поэтому данные
  такие же свежие, как без воркера.
- Доступ к данным портала есть только у того, у кого есть его вебхук: ключ — SHA-256 от вебхука.
  Вебхуки хранятся в D1 вашего аккаунта Cloudflare.
- Лиды, звонки и задачи по-прежнему грузятся из Bitrix24 напрямую, на сервере — только сделки.
